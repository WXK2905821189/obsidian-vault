# 项目目录结构规范

初始化新项目那天，你通常直接让 AI 开工。两天后仓库里躺着 47 个文件：三份 README，其中两份是 AI 自作主张生成的；一份 feature_list 和一份 feature_list(1)；六个散落在 src 目录里的 .md。文档不是没写，是没地方放。AI 每次都要靠猜判断哪份有效，猜错的成本由你付。

目录结构是第一层约定，比任何写作规范都先被读到。它回答三个问题：根目录放什么，docs 里怎么分，什么情况才建新目录。回答清楚，AI 不翻文件就能定位；回答不清，规范写得再好也落不了地。

## 根目录最小集

根目录只放五类文件，每个都有不可替代的职责：

| 文件 | 职责 |
| --- | --- |
| README.md | 一句话说明项目是什么，链接到 docs/ 的入口文档 |
| AGENTS.md | 给 AI 的项目约定，全局指令，任何工具都能读 |
| CLAUDE.md | Claude Code 的指令文件，内容与 AGENTS.md 对齐 |
| CHANGELOG.md | 变更日志，记录每次版本变化，格式见命名编号与格式约定 |
| feature_list.md | 功能清单，一行一个功能，标注状态与对应 Spec ID |

最小集的意思是：这五类之外，不再往根目录放其他 Markdown。判断标准是一句话——这个文件是否每个会话都必须知道。如果是，放根目录；如果只是偶尔需要，放 docs/ 按需读。根目录是常驻上下文，塞进太多文件，等于每次会话都让 AI 读一遍无关内容。项目记忆不单独建文件，直接写进 AGENTS.md，与文档全景图的最小文档集相互呼应。

## docs 子目录分类

docs/ 下按文档类型分四类目录，对应文档全景图的七类文档，按用途合并：

```
docs/
├── specs/         需求 Spec，按功能 ID 命名，见 02 篇
├── adrs/          决策记录，ADR-001 起编号，见 03 篇
├── tds/           技术设计文档，大改动才写，平时可能为空
└── sessions/      会话交接，每次会话结束更新，含进度状态
```

四类目录各管一个问题：specs/ 管"做什么"，adrs/ 管"为什么"，tds/ 管"怎么做"，sessions/ 管"现在到哪"。目录名即索引，找文档靠路径不靠记忆。项目记忆归入根目录 AGENTS.md，不单独设目录；进度与交接合并进 sessions/，减少目录数量。

## 与文件夹深度原则的协调

知识库设计有一条原则：文件夹深度不超过两层，便于导航，出处是 [[07-学习成长/知识管理体系/04_知识库的结构设计：从混乱到有序|知识库结构设计]]。docs/ 的结构恰好符合：根目录是第 0 层，docs/ 是第一层，specs/ 等分类目录是第二层，文件全部在第二层平铺，不再往下嵌套。

出现嵌套冲动的信号是某个分类目录文件超过 20 个。此时不要加第三层子目录，而是横向拆分：比如 tds/ 按模块拆成 tds-ui/ 与 tds-core/，或把过期文档移入 archive/。文件多了先考虑横向切分，不要纵向挖深。

## 目录规范的适用边界

这条规范只约束根目录与 docs/，不约束 src/ 的代码结构。代码目录由框架和语言生态决定，强行统一反而别扭；文档目录只有一套，怎么放都不会和框架冲突。改动代码结构的人未必想到文档，但文档结构的统一成本极低，值得先固化。

## 两版示例

个人项目最小目录，两周迭代的原型足够用：

```
project/
├── README.md
├── AGENTS.md
├── CHANGELOG.md
├── feature_list.md
└── docs/
    ├── specs/       T-001-xxx.md
    └── sessions/    2026-08-11.md
```

个人版连 tds/ 和 adrs/ 都可以先不建，等到出现第一个技术选型再补 adrs/，出现第一个大设计再补 tds/。目录跟随需求长出来，而不是初始化时铺满空壳。

团队完整目录，长周期产品在个人版之上加索引和模板：

```
project/
├── README.md
├── AGENTS.md
├── CLAUDE.md
├── CHANGELOG.md
├── feature_list.md
└── docs/
    ├── specs/
    │   ├── SPECS.md         索引表
    │   └── T-001-xxx.md
    ├── adrs/
    │   ├── ADR-INDEX.md
    │   └── ADR-001-xxx.md
    ├── tds/
    │   └── TDS-001-xxx.md
    ├── sessions/
    └── Templates/           模板体系，见 04 篇
```

两版差别只在索引文件和模板目录，分类骨架完全一致。团队版从个人版长出来，而不是一步到位。

> [!tip] 目录结构是 AI 的导航地图。AI 不靠记忆找文件，靠路径和命名。两层平铺加清晰命名，是成本和效率的最佳平衡点；深度超过两层，AI 大概率漏读，目录等于白建。

## 现在你应该怎么做

1. 打开现有项目仓库，对照根目录最小集，把多出来的 Markdown 移进 docs/，删除重复的 README。
2. 按 specs、adrs、tds、sessions 建四个 docs 子目录，同类文档归位。
3. 建 feature_list.md，一行一个功能，标注状态，编号规则见命名编号与格式约定。
4. 在 AGENTS.md 里写一段"文档位置约定"，告诉 AI 各类文档去哪找、找不到时新建在哪。
5. 下一个项目初始化时，先把目录树建好再让 AI 开工，别等文件散乱后再收拾。
