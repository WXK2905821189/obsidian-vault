# 完整项目文档集示例

> 本文以"轻账本"（个人记账 Web 应用）为例，给出一个真实项目从零到一应建立的全部文档模板。每份模板按章节给出，复制到自己的项目里，替换项目名与细节即可直接使用。

## 开场场景

你是一名独立开发者，要做"轻账本"：单用户个人记账 Web 应用，无账号无登录，数据存本地，打开即记，月底一键导出。技术栈定为 Next.js 15 + React 19 + TypeScript + SQLite + TailwindCSS 4，全栈单一仓库。

一个项目的文档集等于四类文档的组合：入口文档（README / AGENTS / CLAUDE）、产品文档（PRD / SPEC）、技术文档（ADR / TDS）、状态文档（progress / feature_list / CHANGELOG / sessions）。完整目录结构如下：

```text
ledger-app/
├── README.md               # 入口：项目是什么，人先读
├── AGENTS.md               # 入口：AI 代理工作规范，AI 先读
├── CLAUDE.md               # 入口：Claude 会话上下文
├── progress.md             # 状态：当前焦点与下一步
├── CHANGELOG.md            # 状态：变更日志
├── feature_list.json       # 状态：功能清单与测试通过数
├── docs/
│   ├── PRD.md              # 产品：做什么不做什么
│   ├── specs/
│   │   └── SPEC-001-记账录入.md
│   ├── adrs/
│   │   └── ADR-001-选型SQLite.md
│   └── tds/
│       └── TDS-001-记账功能.md
├── sessions/
│   └── 2026-08-11.md       # 状态：会话交接
└── src/                    # 源代码
```

> [!tip] 关键洞察
> 文档集的骨架是"入口 + 产品 + 技术 + 状态"四类，与 [[05-产品与开发/AI驱动Web应用开发/02-文档体系篇/01_文档全景图|文档全景图]] 一一对应。写作顺序与阅读顺序不同：先写 README 和 PRD 让方向成立，随开发补 SPEC、ADR、TDS，progress 与 CHANGELOG 持续更新。每份文档只回答一个问题，多答少答都会腐烂。

## README 模板

README 回答两个问题：这是什么、怎么跑。个人项目也要写，它是所有后续文档的入口。完整模板：

````markdown
# 轻账本 Ledger App

单用户个人记账 Web 应用。无账号无登录，数据存本地 SQLite，隐私优先。

## 快速开始

```bash
npm install
npm run dev
# 打开 http://localhost:3000
```

## 技术栈

| 项 | 选择 |
| --- | --- |
| 框架 | Next.js 15 App Router |
| 语言 | TypeScript 5（严格模式） |
| 数据库 | SQLite（better-sqlite3） |
| 样式 | TailwindCSS 4 |

## 目录说明

| 路径 | 说明 |
| --- | --- |
| `src/app` | 页面与路由 |
| `src/lib` | 数据层与工具函数 |
| `src/components` | 可复用组件 |
| `docs/` | 产品与技术文档 |
| `sessions/` | 会话交接记录 |

## 常用命令

```bash
npm run dev     # 开发服务器
npm run build   # 生产构建
npm test        # 单元测试
npm run lint    # 代码检查
```

## 相关文档

- 产品需求：docs/PRD.md
- 功能规格：docs/specs/
- 架构决策：docs/adrs/
````

模板中的"目录说明"与"相关文档"两节是地图，防止新加入者迷路。写 README 不必等开发完成，开工第一天放个骨架即可。

## AGENTS 模板

AGENTS.md 给 AI 代理（Cline、Codex、Trae 等）读，回答"在这个仓库里怎么干活"。编写规范见 [[05-产品与开发/AI驱动Web应用开发/03-上下文篇/01_AGENTS.md编写规范|AGENTS.md]]。完整模板：

````markdown
# AGENTS.md

本项目为 AI 代理提供工作规范。修改本仓库代码前必读。

## 技术栈

- Next.js 15 App Router，TypeScript 严格模式
- 数据库：SQLite（better-sqlite3），无 ORM，原生 SQL
- 样式：TailwindCSS 4，禁止内联 style

## 构建与测试命令

| 命令 | 用途 | 要求 |
| --- | --- | --- |
| `npm run dev` | 开发服务器 | 无 |
| `npm run build` | 生产构建 | 必须通过 |
| `npm test` | vitest 测试 | 新增代码必须带测试 |
| `npm run lint` | eslint 检查 | 提交前必须通过 |

## 代码约定

- 组件一律函数组件加 hooks，不用 class 组件
- 数据访问收敛到 `src/lib/db.ts`，组件内禁止直接写 SQL
- 提交信息用 Conventional Commits：`feat:` `fix:` `docs:` `refactor:`
- 新功能先写 SPEC 验收标准，再写实现

## 关键约束

- 不引入 ORM，不引入状态管理库
- 不新增登录、多用户、云同步，超范围需求先拒绝
- 每次改动前读 `progress.md` 与最新 `sessions/`
- 破坏性变更必须更新 CHANGELOG.md，涉及选型新增 ADR
````

AGENTS.md 的每条约束都要能执行、能检查。写"代码要优雅"这类无法验证的废话等于没写。

## CLAUDE 模板

CLAUDE.md 是 Claude Code 的会话上下文，回答"每次开工先看什么"。编写规范见 [[05-产品与开发/AI驱动Web应用开发/03-上下文篇/02_CLAUDE.md编写规范|CLAUDE.md]]。完整模板：

````markdown
# CLAUDE.md

Claude Code 在本仓库的工作上下文。每次会话开始自动加载。

## 项目概览

轻账本：单用户个人记账 Web 应用。Next.js + SQLite，数据全部存本地，无账号体系。

## 每会话必读清单

1. `progress.md` — 当前焦点与下一步
2. `feature_list.json` — 功能实现与测试状态
3. `sessions/` 最近一次记录 — 遗留事项

## 规则导入

- 工作规范：见 AGENTS.md
- 产品边界：见 docs/PRD.md 的"不做什么"
- 架构约束：改动前读 docs/adrs/
- 新功能流程：SPEC 先行，TDS 跟进，测试兜底
````

CLAUDE.md 与 AGENTS.md 有重叠，职责划分：AGENTS.md 写"必须遵守的规则"，CLAUDE.md 写"每次会话要读什么"。个人项目可合并，团队项目建议分开。

## PRD 模板

PRD 回答"做什么、不做什么"。写法参考 [[05-产品与开发/AI驱动Web应用开发/02-文档体系篇/03_需求文档|需求文档]]。完整模板：

````markdown
# PRD 轻账本

## 产品目标

两周内交付可日常使用的记账应用：打开即记，数据本地存储，月底可导出账单。

## 目标用户

- 主用户：开发者本人
- 特征：记账频率低，怕麻烦，重视隐私，单设备使用

## 核心功能

1. 记账录入：金额、分类、备注、日期
2. 分类管理：预设分类加自定义
3. 账单列表：时间倒序，按月筛选
4. 月度汇总：收支统计
5. 数据导出：CSV 下载

## 不做什么

- 不做多用户、登录、云同步
- 不做预算、提醒、报表分析
- 不做手机端，仅桌面浏览器

## 成功指标

- 每周记账不少于 5 次
- 单笔录入小于 10 秒
- 数据零丢失，导出 CSV 可被 Excel 打开
````

"不做什么"是全文档最重要的一节。AI 提需求时，边界比功能更能挡无用功。

## SPEC 模板

每个功能一份 SPEC，先写验收标准再写代码。验收标准用 Given-When-Then 格式，让 AI 可执行、可测试。完整模板：

````markdown
# SPEC-001 记账录入

## 用户故事

作为用户，我想快速记一笔账，以便月底回顾支出。

## 验收标准

场景：录入一笔新账单

- Given 我在"记一笔"表单页
- When 我填写金额 35.50 元、分类"餐饮"、备注"午饭"并提交
- Then 账单列表第一条显示该记录，金额、分类、备注全部正确

场景：金额非法

- Given 表单金额为空、为负数或含非法字符
- When 我点击提交
- Then 表单显示错误提示，数据库无新记录

## 不做什么

- 不做语音记账、拍照识别
- 不做重复账单自动检测

## 技术约束

- 金额以整数分存储，避免浮点误差
- 写入统一走 `src/lib/db.ts`
- 分类取自预设集合，v0.2 再开放自由输入

## 反面示例

- 金额用 `number` 直接存储：0.1 加 0.2 类浮点误差
- 组件内拼 SQL：注入风险且难测试
- 提交前不校验：脏数据进库后极难清理
````

"反面示例"一节是给 AI 的负样本。写清"不要怎么做"，比只写"怎么做"更能约束行为。

## ADR 模板

决策记录回答"为什么这样选"。一条决策一个文件，状态从"提议"到"已接受"。写法参考 [[05-产品与开发/AI驱动Web应用开发/02-文档体系篇/05_决策记录ADR|决策记录ADR]]。完整模板：

````markdown
# ADR-001 数据库选型 SQLite

状态：已接受
日期：2026-08-11

## 背景

记账应用需要持久化账单数据，需要确定数据库方案。单用户、单设备、数据量小。

## 方案对比

| 方案 | 优点 | 缺点 |
| --- | --- | --- |
| SQLite | 零部署，单文件，备份等于复制 | 不擅多写并发 |
| PostgreSQL | 功能强，生态成熟 | 需服务器与运维 |
| JSON 文件 | 实现最简单 | 查询聚合弱，一致性差 |

## 决策

采用 SQLite（better-sqlite3）。单用户场景并发写入压力为零，SQLite 完全满足，运维成本最低。

## 后果

- 数据文件 `data/ledger.db` 纳入备份与 git 忽略策略
- 未来多设备同步需整体迁移，迁移成本由 ADR-002 承接
- 备份等于复制文件，无需数据库 dump

## 被否决方案

- PostgreSQL：单用户场景过度设计，服务器与运维成本不值
- JSON 文件：月度聚合查询需全量读入内存，功能扩展受限
````

ADR 只记录"有取舍"的决策。默认选项、顺手为之的选择不写，写了就成了噪音。

## TDS 模板

技术设计文档回答"怎么实现"。一个功能一份，列变更文件清单，让 AI 明确改动边界。完整模板：

````markdown
# TDS-001 记账功能

关联：SPEC-001、ADR-001

## 目标

实现记账录入完整链路：表单、校验、写入 SQLite、列表刷新。

## 方案

- `src/lib/db.ts`：初始化数据库，暴露 `insertTransaction` 与 `listTransactions`
- `src/lib/validate.ts`：金额与分类校验，返回错误信息
- `src/app/page.tsx`：记账表单与账单列表同页
- 金额以分存储，展示时前端换算为元

## 变更文件清单

- 新增：`src/lib/db.ts`
- 新增：`src/lib/validate.ts`
- 新增：`src/lib/db.test.ts`
- 修改：`src/app/page.tsx`

## 风险

- 中：better-sqlite3 原生模块在 Next.js 构建期的兼容性
- 低：校验遗漏导致脏数据，以测试兜底
````

TDS 与 SPEC 的分工：SPEC 管"什么是对的"，TDS 管"怎么改文件"。AI 拿到 TDS 就能直接开工。

## 进度文档模板

progress.md 是单文件状态的真相来源，回答"现在到哪了"。写法参考 [[05-产品与开发/AI驱动Web应用开发/02-文档体系篇/06_进度与状态文档|进度与状态文档]]。完整模板：

````markdown
# 进度与状态

更新：2026-08-11

## 当前焦点

记账录入链路（SPEC-001）收尾，剩余表单错误提示 UI。

## 最近变更

- 2026-08-11 完成 SQLite 接入，录入接口可用
- 2026-08-09 确定技术选型（ADR-001）

## 下一步

1. 表单错误提示 UI
2. 月度汇总视图
3. CSV 导出

## 已知问题

- 浏览器刷新后表单内容丢失（未做草稿保存，接受现状）
- 金额在部分浏览器存在显示截断（低优先级）
````

progress.md 要克制：只记焦点、变更、下一步、已知问题四节。写成长篇周报就没人看了。

## 变更日志模板

CHANGELOG.md 记录每个版本的增删改，按 Keep a Changelog 格式。完整模板：

````markdown
# 变更日志

格式遵循 Keep a Changelog，版本遵循语义化版本。

## [0.1.0] - 2026-08-11

### 新增

- 记账录入：金额、分类、备注、日期（SPEC-001）
- 分类预设与自定义
- SQLite 本地存储（ADR-001）
- 账单列表按时间倒序

### 修复

- 金额小数位显示截断

### 技术

- 初始化 Next.js 15 + TypeScript 项目
- 接入 better-sqlite3
````

个人项目可只在版本发布时写一次。AI 生成的变更日志要人工核对，重点检查"修复"项是否对应真实 bug。

## 会话交接模板

每次会话结束写一条 sessions 记录，让下一次会话（无论人还是 AI）无缝接上。完整模板：

````markdown
# 会话 2026-08-11

## 目标

完成记账录入链路（SPEC-001）。

## 完成

- [x] SQLite 接入（ADR-001）
- [x] 录入接口与校验逻辑
- [ ] 表单错误提示 UI（遗留）

## 决策

- 金额统一以分存储
- 数据访问统一走 `src/lib/db.ts`

## 遗留事项

- 表单错误提示 UI，下个会话优先处理
- 复核 `validate.ts` 边界用例

## 交接

下次会话先读 progress.md。当前焦点：表单错误提示 UI。
````

交接文档的验收标准：一个陌生人读完后，能在 5 分钟内说出"下一步做什么、从哪里开始"。

## 现在你应该怎么做

新项目初始化，按此顺序建文档，共三步：

**第一步：开工首日建三个入口文档。** 创建 README.md（项目是什么）、AGENTS.md（AI 工作规范）、CLAUDE.md（会话上下文）。每份一句话也行，先把位置占住，日后再补。

**第二步：需求与选型时写产品与技术文档。** 产品边界确认后写 docs/PRD.md，"不做什么"当天写清。每敲定一个关键技术选型，当天写一条 ADR。宁可少而准，不可多而空。

**第三步：每个功能走完整循环。** 开工前写 SPEC（先写验收标准），动手前写 TDS（变更文件清单），完成后更新 feature_list.json 与 progress.md，有版本更新写 CHANGELOG.md，收尾写一条 sessions 交接。

> [!tip] 关键洞察
> 这份文档集是整个知识库最有价值的"弹药"：它不是知识，而是可以直接上手的模板。文档的收益在复用期，不在写作期。今天花 10 分钟建好入口文档，三个月后 AI 接手项目时省下的是几小时的重建成本。核心纪律只有两条：先写验收标准再写代码，决策留痕。
