# 个人复盘与迭代：让每个项目都增值

> [!abstract] 本层要练成的能力
> 个人做项目，最大的复利不是做完一个，而是**做完后沉淀成可复用的方法论和资产**。本层要练成的能力是：**每次复盘都产出"至少 1 个可复用资产 + 1 个行动项"，并坚持"一次一动"的棘轮式迭代，让每个项目都成为下一个项目的杠杆。**
> 这是模块一的收尾：前面三层解决"怎么把项目做完"，这一层解决"做完之后怎么让它增值"。

---

## 一、深度讲透：复盘为什么容易流于形式

### 因为…所以…：复盘失败的三个根因

- **因为**复盘如果没有"数据"支撑，就会退化成"我觉得还行/不太行"，**所以**复盘必须从"记录目标与实际的差距（数值）"开始，没有数字就没有复盘。
- **因为**人倾向于"合理化"自己的失败（找外部原因），**所以**复盘要逼自己问"根本原因"而不是"表面现象"——表面原因是"模型效果差"，根本原因可能是"没定义评测标准"。
- **因为**复盘若没有"行动项"，就只是一次"感想会"，**所以**每次复盘必须产出"下次要改的一个动作"，否则等于没复盘。

> [!warning] 反例坑：三种"伪复盘"
> 1. **复盘=写感想**：写了一大段"学到了很多"，但没有一个可复用资产、没有一个行动项。
> 2. **只复不复**：复盘了但下次还是老样子——因为没把结论固化成"下次直接用的模板/清单"。
> 3. **复盘无数据**：凭感觉判断成败，导致"错误归因"，下次在同一个坑里再摔一次。

## 二、填完即用：复盘四问模板 + 月度复盘模板

### 模板 1：轻量复盘四问（每个项目/每个里程碑后）

```
① 结果如何？：目标与实际的差距（数值）________
② 为什么？：根本原因（再问一次"为什么"，直到挖到机制层）________
③ 学到了什么？：可迁移的方法/认知 ________
④ 沉淀了什么？：下次能直接复用的模板/清单/资产 ________
```

> 关键差异在第④问：**复盘的产出应该是"可复用的资产"，而不只是"我学到了"**。第④问答不出来，这次复盘就不算完成。

### 模板 2：月度复盘（把项目级复盘串成能力成长线）

```
本月完成了哪些里程碑/项目？：________
本月最大的一个判断失误是什么？：________
本月沉淀了哪些可复用资产？：________
下月要刻意练的一个能力是什么？：________
```

> 月度复盘的作用：把"项目级复盘"升级为"能力级复盘"——不只问"项目做得怎样"，更问"我作为 PM 的能力有没有长进"。

## 三、个人迭代的"棘轮"原则

> 迭代最怕的是"来回打转"。用**棘轮原则**：每轮只做一处改变，且方向先验证再加深。

| 原则 | 做法 |
|------|------|
| 一次一动 | 每轮只改一处，避免变量混淆 |
| 先验证再加深 | 先看方向对不对，再加大力度 |
| 可回退可对比 | 改动前后有对比，能回退 |

### 因为…所以…：为什么"一次一动"在 AI 项目里是铁律

- **因为**AI 项目的效果由"模型 + 提示词 + 知识库 + 配置"多个变量共同决定，**所以**一次改多处，出了问题根本定位不到是哪一环（这正是 [[05-产品与开发/AI项目实战管理/02-AI特有管理篇/02_评测驱动迭代]] 要解决的）。
- **因为**棘轮只进不退，**所以**每轮改动前要先确认"方向对"，否则会在错误方向上越走越远。

> 这是你在知微机器人"周复盘+错题集"和 InterviewPrep 迭代中都在用的底层逻辑，系统化后就是你的迭代方法论。

## 四、从复盘到"项目资产"

> 个人项目做完，至少要沉淀三样可复用资产：

| 资产 | 示例 |
|------|------|
| 方法论模板 | 复盘四问、里程碑清单、能力判断框架 |
| 项目案例 | 一个能讲的故事（6段式） |
| 技术/内容资产 | Prompt、脚本、知识库结构、文档模板 |

> 这三样，正是面试时"作品集"和"能力证明"的来源，也是你建众多知识库的价值所在。衔接 [[05-产品与开发/AI项目实战管理/04-求职表达篇/02_个人AI项目讲成能交付的作品]]。

## 五、一次"有效复盘"案例（抽象示例）

```
项目：做一个AI内容摘要工具
① 结果：上线2周 30 个用户，留存 20% → 未达预期
② 原因：核心不是"摘要质量"，而是没有稳定触发场景/入口
③ 学到：工具类产品，场景与入口决定留存，不止功能
④ 沉淀：新增"触发场景分析"模板到个人PM方法库；案例入作品集
```

## 七、练什么（D4 练习，可自测）

1. **复盘演练**：用复盘四问模板，复盘知微机器人最近一次迭代（或你最近一个项目），重点填第④问"沉淀了什么"。
2. **棘轮演练**：选一个正在迭代的功能，规定"本轮只改一处"，并写下改动前后的对比方式。
3. **资产盘点**：列出你目前能复用的"方法论模板 + 项目案例 + 技术资产"各 3 样，缺的标出来。
