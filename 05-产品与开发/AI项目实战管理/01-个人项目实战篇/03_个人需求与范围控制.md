# 个人需求与范围控制：遏制范围蔓延

> [!abstract] 本层要练成的能力
> 一个人做项目时，**范围蔓延（scope creep）比团队项目更隐蔽、更致命**——因为没有人拦住你"再加一个功能"的冲动。本层要练成的能力是：**对任何新冒出来的需求，30 秒内给出"做 / 不做 / 缓"的判断，并用一个需求池让想法"被记住但不干扰推进"。**
> 承接上一层的"最小闭环"：环转起来了，这一层解决"怎么不让它越转越乱"。

---

## 一、深度讲透：范围蔓延为什么是个人项目的头号杀手

### 个人项目范围蔓延的三个伪装

| 伪装的理由 | 真相 |
|-----------|------|
| "再多做一个功能就更完整了" | 往往是逃避核心闭环没做好的规避 |
| "这个技术很前沿，想试试" | 好奇心驱动，而非用户价值驱动 |
| "顺手加上，不费事" | 每个"顺手"累积成巨大的范围膨胀 |

### 因为…所以…：为什么"我想要"会伪装成"用户需要"

- **因为**人是损失厌恶的：已经投入的时间/精力（沉没成本）会让人想"再加把劲把它做完"，**所以**越做到后面，越难砍掉新想法——砍掉等于承认前面的投入"白费"。
- **因为**AI 领域新东西层出不穷，好奇心天然被高频触发，**所以**"试试新技术"的冲动会不断出现；**而**新技术 ≠ 用户价值，**所以**必须用"用户价值"而不是"新鲜感"来过滤。
- **因为**个人项目没有"产品评审会"这道外部闸门，**所以**所有"顺手加"都会直接进开发队列，**所以**必须自己造一道闸门（需求池 + 拷问清单）。

> [!warning] 反例坑：两种"范围失控"
> 1. **"顺手"累积**：每个功能单独看都"不费事"，三个月后项目膨胀到原计划的 3 倍，核心闭环反而没做好。
> 2. **"永不上线"**：总想"再完整一点再发"，结果项目永远停在"开发中"，最早那批用户永远等不到。

## 二、克制范围的判断力：一句话拷问

> 每次想加功能前，用一句话拷问自己：

> **"砍掉它，我的闭环还转得起来吗？"**
> - 砍掉还能转 → 不加（至少先记 Todo，等 P0 验证）
> - 砍掉就卡住 → 才值得现在做

> 这套逻辑就是你在 InterviewPrep 里用的 P0/P1/P2（详见 [[05-产品与开发/AI项目实战管理/01-个人项目实战篇/02_最小闭环与里程碑]]）。

## 三、填完即用：需求池模板 + 范围拷问清单

### 模板 1：需求池（让大脑空出来的仓库）

> 所有想法先丢进需求池，不立刻做。不是每个想法都要做，记录下来就是为了"记住它、却不受它干扰"。

```
| 需求 | 来源（用户/自己/灵感） | 价值假设 | 优先级（P0/P1/P2/不确定） | 状态（池/排期/砍掉/已做） |
|------|----------------------|---------|--------------------------|--------------------------|
|      |                      |         |                          |                          |
```

> 规则：每周清点一次需求池，把"不确定"的要么升级为 P1，要么砍掉。池子不清理，就会变成"第二个待办清单"。

### 模板 2：范围拷问清单（加功能前过一遍）

```
□ 砍掉它，闭环还转得起来吗？（转得起来 → 缓）
□ 它服务的是"用户价值"还是"我的好奇心"？（好奇心 → 缓）
□ 现在做它，会推迟 M2/M3 里程碑吗？（会 → 缓）
□ 有没有更便宜的验证方式（先做最小版/先问用户）？（有 → 先验证）
```

> [!tip] "缓"不等于"不做"
> 把"缓"的需求写进需求池并标注 P1/P2，等 P0 闭环验证后再回头。这样既不丢想法，也不被想法绑架。

## 四、何时该"及时收尾"而非"继续蔓延"

> 个人项目另一个大坑是**永不上线**。给项目设"完成条件"：
- 做到 M2（闭环跑通）就**先发一版**，接受不完美
- "做完"比"做完美"重要得多

> 用你建议的判断：**首发版本的核心是"能让最早的一批用户用上并给反馈"，而不是"功能齐全"。**

## 六、练什么（D4 练习，可自测）

1. **需求池演练**：把 InterviewPrep 或 Skill四连发"想加但没加"的功能列进需求池，用范围拷问清单逐个判定"做/缓/砍"。
2. **砍功能演练**：假设项目已延期两周，从当前功能里砍掉 30%，用"砍掉还转吗"决定砍哪些。
3. **收尾演练**：给一个存量项目设"完成条件"，判断它当时是否"该上线没上线"。

## 七、怎么算会（D3 判据）

- [ ] 能对任何新功能 30 秒内给出"做 / 缓 / 砍"判断，并说出依据
