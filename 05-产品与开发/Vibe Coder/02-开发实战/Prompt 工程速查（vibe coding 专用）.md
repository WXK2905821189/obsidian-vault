# Prompt 工程速查（vibe coding 专用）— 拿来即用的 Prompt 模板

> [!abstract] 这篇解决什么问题
> 不需要学「Prompt 工程」理论。==直接复制粘贴，根据场景填入你自己的内容就行。== 覆盖从项目启动到迭代维护的 10 个高频场景。
>
> 前置阅读：[[05-产品与开发/Vibe Coder/Vibe Coder 常见问题全景图#1.3 不知道怎么跟 AI 描述需求]]

---

## 一、万能 Prompt 公式

```
【做什么】+ 【在哪做】+ 【期望效果】+ 【约束条件】+ 【我零基础】
```

> [!example] 示例
> 「帮我做一个网页版记账软件（做什么），在首页显示本月收支（在哪做），能添加收入和支出记录，自动计算余额（期望效果）。页面要简洁，不需要登录功能（约束条件）。我零基础，每一步请解释（我零基础）。」

## 二、10 个高频场景模板

### 场景 1：项目启动 — 从 0 开始

```
"我要做一个 [产品名称]，核心功能是 [一句话描述]。
我零基础，请帮我：
1. 先推荐技术方案（2-3 个选项，说明优缺点，我来选）
2. 选好技术方案后，帮我搭建项目
3. 每一步解释你在做什么、为什么"
```

### 场景 2：项目启动 — 先做架构设计

```
"在开始写代码之前，先帮我做一个架构设计：
1. 这个项目应该分成哪几个模块？
2. 每个模块负责什么？
3. 模块之间怎么通信？
画一个简单的架构图。不要写代码，先出方案。"
```

### 场景 3：加新功能 — 迭代防退化

```
"在保持以下现有功能完全不变的前提下，添加 [新功能]：
[列出 3-5 个核心功能]

优先通过新增代码实现，尽量避免修改已有文件。
如果必须修改已有文件，请先列出修改清单和原因，等我确认。
改完后，帮我列出所有被修改的文件，以及每个修改可能影响哪些已有功能。"
```

### 场景 4：加新功能 — 先出方案再动手

```
"我要加 [新功能]，先不要改代码。请告诉我：
1. 你打算修改哪些文件？
2. 每个文件改什么？为什么？
3. 这些改动可能影响哪些已有功能？
4. 有没有不需要修改文件就能实现的方式？
等我确认后再动手。"
```

### 场景 5：报错排查 — 快速定位

```
"运行时报了这个错：[粘贴完整报错信息]
1. 这个报错是什么意思？用大白话解释
2. 最可能的原因是什么？
3. 怎么解决？给出具体的操作步骤"
```

### 场景 6：报错排查 — 深度诊断

```
"我做了一个 [操作]，期望 [预期结果]，但实际 [实际结果]。
浏览器控制台报错：[粘贴报错]
这个问题可能涉及哪些文件？帮我逐一排查。"
```

### 场景 7：UI 调整 — 精确描述

```
"帮我修改 [页面/组件名称]：
- 位置：[在哪里]
- 样子：[什么颜色、大小、形状]
- 交互：[点击/悬停后什么效果]
- 参考：[如果有一个参考页面或图片，描述或贴出来]
只改这个组件，不要影响其他页面。"
```

### 场景 8：代码审查 — 防止 AI 埋坑

```
"帮我检查以下代码有没有问题：
1. 有没有安全漏洞？（密钥泄露、SQL 注入等）
2. 有没有明显的性能问题？
3. 有没有逻辑错误？
4. 有没有可以简化的地方？
[粘贴代码]"
```

### 场景 9：项目交接 — 生成 README

```
"帮我写一份 README.md，用中文，说明：
1. 这个项目做什么
2. 怎么启动（npm install + npm run dev）
3. 怎么打包（npm run build）
4. 项目结构：每个文件夹放什么
5. 用了哪些技术
6. 有哪些注意事项"
```

### 场景 10：功能清单 — 生成回归测试清单

```
"帮我列出当前项目中所有已实现的功能，每个功能一行，
作为回归测试清单。格式：
- [ ] 功能名称：一句话描述 + 测试方法（怎么验证它正常）"
```

## 三、特定场景的约束话术

### 告诉 AI 不要做什么

| 话术 | 场景 |
|---|---|
| "不要修改已有功能的代码，只新增文件" | 加新功能时 |
| "不要改 UI 样式，只改逻辑" | 修 bug 时 |
| "不要引入新的依赖包" | 项目已稳定时 |
| "不要用 TypeScript，用 JavaScript" | 你不想学 TS 时 |
| "不要用数据库，用本地 JSON 文件存储" | 不需要后端时 |

### 让 AI 解释清楚

| 话术 | 场景 |
|---|---|
| "每一步解释你在做什么、为什么" | 所有场景通用 |
| "用大白话解释，不要用术语" | 看不懂时 |
| "给我 2-3 个方案，说明优缺点，我来选" | 不确定怎么做时 |
| "这个方案有什么风险？有没有更简单的方式？" | 审查方案时 |

### 让 AI 自我检查

| 话术 | 场景 |
|---|---|
| "检查一下你生成的代码有没有问题" | 生成后 |
| "你确定吗？请逐一检查每个文件" | AI 说「没问题」时 |
| "这个方案是哪个官方文档里写的？给我链接" | AI 给出可疑方案时 |
| "检查一下我说的需求有没有矛盾的地方" | 需求复杂时 |

## 四、常见错误 Prompt 对比

| ❌ 差的 Prompt | ✅ 好的 Prompt | 差在哪 |
|---|---|---|
| "帮我做一个软件" | "帮我做一个网页版记账软件，能添加收支、显示余额。页面简洁，不需要登录。我零基础，每一步请解释。" | 太笼统，AI 只能猜 |
| "加个功能" | "在首页右上角加一个「导出 Excel」按钮，点击后把当前月账单下载为 .xlsx。" | 没说在哪、做什么、怎么交互 |
| "修一下 bug" | "点击搜索按钮后页面刷新了，应该是不刷新、直接在下面显示搜索结果。控制台没有报错。" | 没说期望行为和实际行为 |
| "风格要好看一点" | "用蓝色和白色做主色，按钮圆角，卡片有阴影，像 Apple 官网那种简洁风格。" | 主观描述，AI 无法理解 |
| "帮我用 React 做" | "我需要做一个用户登录功能，你推荐用什么方式实现？给我 2-3 个方案，说明优缺点，我来选。" | 替 AI 做了技术决策 |

## 五、进阶技巧

### 技巧 1：逐步细化

```
第一轮："做一个博客网站"
第二轮："博客首页显示文章列表，每篇文章有标题、摘要、发布时间"
第三轮："文章列表按发布时间倒序排列，每页显示 10 篇，底部有分页"
第四轮："文章详情页有标题、正文、标签、上一篇/下一篇导航"
```

### 技巧 2：用示例代替描述

```
"按钮的样式参考这个描述：蓝色背景、白色文字、圆角 8px、鼠标悬停时颜色变深"
```

### 技巧 3：分步骤给指令

```
"先做 Step 1：创建文章列表页面，用假数据展示"
→ 确认 OK
"Step 2：把假数据换成从 Markdown 文件读取"
→ 确认 OK
"Step 3：添加分页功能"
```

> [!tip] 这个技巧结合 [[05-产品与开发/Vibe Coder/02-开发实战/Vibe Coding 迭代防退化指南]] 的「一次只改一个」原则，效果最好。

## 六、一句话总结

> [!tip] Prompt 好坏 = 具体程度 × 约束清晰度
> ==描述「用户看到什么、能做什么」，不说「用什么技术」。== 每次加一个约束（不要改已有功能、先用假数据、先出方案），就能大幅降低 AI 跑偏的概率。
