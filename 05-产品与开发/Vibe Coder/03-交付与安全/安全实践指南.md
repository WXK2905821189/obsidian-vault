# 安全实践指南 — 密钥、API Key、防泄漏全攻略

> [!abstract] 这篇解决什么问题
> 零基础 Vibe Coder 最容易忽略安全，但后果最严重——==密钥泄露一夜欠几千不是段子。== 这篇覆盖 5 个最常见的安全风险和防护措施。
>
> 前置阅读：[[05-产品与开发/Vibe Coder/Vibe Coder 常见问题全景图#4.3 安全问题——最容易忽略但最危险]]

## 一、最关键的一条：密钥绝不写进代码

> [!danger] 血的教训
> API Key 写在代码里 → 上传到 GitHub → 被别人看到 → 别人用你的额度狂刷 → 一夜欠几千块。==这不是段子，GitHub 上每天都有这样的案例。==

### 什么是「密钥」？

任何看起来像密码的东西：
- API Key（如 `sk-xxx`、`ghp_xxx`）
- Access Token
- Secret Key
- 数据库密码
- 第三方服务密钥

### 正确做法：用 `.env` 文件

```
# 项目根目录下创建 .env 文件
# 把密钥写在这里，不要写在代码里

OPENAI_API_KEY=sk-xxxxxxxxxxxx
GITHUB_TOKEN=ghp_xxxxxxxxxxxx
DATABASE_URL=postgresql://xxx
```

在代码中引用：

```javascript
// 代码中通过 process.env 读取，不直接写密钥
const apiKey = process.env.OPENAI_API_KEY;
```

> [!tip] 对 AI 说：「帮我把密钥放到 .env 文件里，并在代码中通过环境变量引用。」

---

## 二、`.gitignore` 防护线

`.env` 文件必须加入 `.gitignore`，防止上传到 GitHub。

```
# .gitignore 文件内容（至少包含这些）
node_modules/
.env
.env.local
.env.production
```

> [!tip] 对 AI 说：「帮我创建 .gitignore 文件，确保 .env 和 node_modules 不会被上传到 GitHub。」

### 验证：你的 .env 是否已经泄露？

去你的 GitHub 仓库搜索 `.env` 或 API Key 的前几个字符。如果找到了，==立刻删除那个文件，并去对应平台重置密钥。==

---

## 三、部署时的密钥管理

### 部署到 Vercel

1. 进入 Vercel 项目 → Settings → Environment Variables
2. 添加密钥（和 `.env` 文件内容一样）
3. 重新部署

### 部署到 Railway

1. 进入 Railway 项目 → Variables
2. 添加密钥
3. 自动重启

> [!tip] 对 AI 说：「帮我把 .env 里的环境变量配置到 Vercel/Railway 上，告诉我具体操作步骤。」

## 四、5 个常见安全风险 + 防护

| 风险 | 后果 | 防护 |
|---|---|---|
| API Key 写进代码上传 GitHub | 被盗用，欠费 | 用 `.env` + `.gitignore` |
| `.env` 打包进产物发给用户 | 同上 | Build 后用 `git status` 检查产物 |
| 表单没做校验 | SQL 注入、XSS 攻击 | 对 AI 说：「帮我的表单加上前后端输入校验」 |
| 依赖包有安全漏洞 | 被利用攻击 | 对 AI 说：「帮我检查依赖包有没有已知安全漏洞」 |
| 用户密码明文存储 | 数据库泄露 = 全部密码泄露 | 对 AI 说：「帮我用 bcrypt 加密用户密码」 |

---

## 五、安全自查清单（每次迭代后检查）

```
□ .env 文件是否在 .gitignore 中？
□ 代码中是否有硬编码的密钥？（搜索 sk-、ghp_、token、secret、password）
□ 表单输入是否有校验？
□ 用户密码是否加密存储？
□ Build 产物中是否包含 .env 文件？
```

> [!tip] 对 AI 说：「帮我检查当前项目有没有安全漏洞，列出所有风险点。」

---

## 六、如果密钥已经泄露了怎么办？

1. ==立刻去对应平台重置密钥==（OpenAI、GitHub、Supabase 等）
2. 删除 GitHub 上包含密钥的提交记录
3. 在 `.gitignore` 中添加 `.env`
4. 重新生成密钥，放到 `.env` 中

> [!tip] 对 AI 说：「我不小心把 API Key 上传到 GitHub 了，帮我处理：1. 删除提交记录 2. 告诉我怎么重置密钥。」

---

## 七、一句话总结

> [!tip] 密钥 = 银行卡密码
> ==任何看起来像密码的东西，永远不要写在代码里，永远不要上传到 GitHub。== `.env` + `.gitignore` 是两道最基本的防线。
