# 部署懒人包 — 三步把网页/应用发布到互联网

> [!abstract] 这篇解决什么问题
> 网页在自己电脑上能看，怎么让别人也能访问？==这篇覆盖 4 种最常见项目类型的最简部署方案，每种 3 步就能上线。==

## 一、快速决策：你的项目用哪种部署？

| 你的项目类型 | 用这个 | 费用 | 难度 |
|---|---|---|---|
| 纯静态网页（HTML/CSS/JS） | **GitHub Pages** | 免费 | ⭐ |
| React / Vue / Next.js 前端 | **Vercel** | 免费 | ⭐ |
| 带后端（Node.js/Python） | **Railway** | 有免费额度 | ⭐⭐ |
| 桌面应用（Electron） | **打包成 exe** | 免费 | ⭐⭐ |

---

## 二、方案 A：纯静态网页 → GitHub Pages（免费）

### 适用场景

- 纯 HTML + CSS + JS 项目
- 没有后端，没有数据库
- 或者 `npm run build` 后只有一个 `dist/` 文件夹

### 三步部署

**第 1 步：创建 GitHub 仓库**

> 对 AI 说：「帮我创建一个 GitHub 仓库，把当前项目上传上去。告诉我每一步怎么做。」

或者手动操作：
1. 打开 [github.com](https://github.com)，注册/登录
2. 点击右上角 `+` → `New repository`
3. 仓库名填项目名（如 `my-blog`），选 Public，点 Create

**第 2 步：上传代码**

```bash
# 在项目文件夹中执行
git init
git add .
git commit -m "首次部署"
git branch -M main
git remote add origin https://github.com/你的用户名/仓库名.git
git push -u origin main
```

**第 3 步：开启 GitHub Pages**

1. 在 GitHub 仓库页面 → Settings → Pages
2. Source 选 `Deploy from a branch`
3. Branch 选 `main`，文件夹选 `/ (root)` 或 `/docs`
4. 点 Save，等待 1-2 分钟
5. 访问 `https://你的用户名.github.io/仓库名/`

> [!tip] 如果 `npm run build` 后产物在 `dist/`，让 AI 帮你配置 GitHub Actions 自动部署。

## 三、方案 B：React/Vue/Next.js 前端 → Vercel（推荐）

### 适用场景

- Vite + React / Vue 项目
- Next.js / Nuxt.js 项目
- 任何 `npm run build` 能生成 `dist/` 或 `.next/` 的项目

### 三步部署

**第 1 步：把代码上传到 GitHub**（同方案 A 的第 1-2 步）

**第 2 步：连接 Vercel**

1. 打开 [vercel.com](https://vercel.com)，用 GitHub 账号登录
2. 点击 `New Project`
3. 选择你的 GitHub 仓库
4. Vercel 会自动识别框架（React/Vue/Next.js 等）
5. 点击 `Deploy`

**第 3 步：等待部署完成**

1. 部署完成后，Vercel 会给你一个网址（如 `xxx.vercel.app`）
2. 每次你 `git push` 新代码，Vercel 自动重新部署

> [!tip] Vercel 是最推荐的前端部署方案——自动识别框架、自动 HTTPS、自动 CI/CD、完全免费。

---

## 四、方案 C：带后端项目 → Railway（有免费额度）

### 适用场景

- Node.js + Express 后端
- Python + Flask/FastAPI 后端
- 全栈项目（前后端在一起）

### 三步部署

**第 1 步：把代码上传到 GitHub**

**第 2 步：连接 Railway**

1. 打开 [railway.app](https://railway.app)，用 GitHub 登录
2. 点击 `New Project` → `Deploy from GitHub repo`
3. 选择你的仓库

**第 3 步：配置启动命令**

1. Railway 会自动识别项目类型
2. 如果不是，手动设置：
   - Node.js：`npm start`
   - Python：`python app.py` 或 `uvicorn main:app`
3. Railway 会给你一个网址

> [!tip] Railway 每月有 $5 免费额度，小项目够用。如果流量大，考虑付费或换其他方案。

---

## 五、方案 D：桌面应用 → 打包成 exe

### 适用场景

- Electron 应用
- 需要发给用户安装的桌面软件

### 三步打包

**第 1 步：安装打包工具**

> 对 AI 说：「帮我用 electron-builder 打包这个 Electron 项目，生成 Windows 安装包。」

**第 2 步：执行打包**

```bash
npm run build
# 或
npx electron-builder --win
```

**第 3 步：找到产物**

- 产物在 `dist/` 或 `release/` 文件夹
- 找到 `.exe` 文件，发给用户即可

## 六、部署后常见问题

### 白屏 / 样式丢失

> 原因：资源路径用了绝对路径（`/static/`）而不是相对路径（`./static/`）
>
> 对 AI 说：「Build 后的网页本地打开白屏，帮我把所有资源路径改成相对路径，在 Vite 配置里加 `base: './'`。」

### 刷新后 404

> 原因：前端路由（React Router / Vue Router）在静态部署时刷新会 404
>
> 对 AI 说：「帮我配置 SPA 路由回退，让所有路由都指向 index.html。」

### 接口请求失败（CORS）

> 原因：前端请求了不同域名的后端，被浏览器拦截
>
> 对 AI 说：「后端接口返回了 CORS 错误，帮我配置 CORS 允许跨域请求。」

### 环境变量（API Key）没生效

> 原因：`.env` 文件没有上传到部署平台
>
> 对 AI 说：「帮我把环境变量配置到 Vercel/Railway 上，告诉我具体操作步骤。」

## 七、方案选择速查表

| 你的情况 | 推荐方案 |
|---|---|
| 纯 HTML/CSS/JS，不需要后端 | GitHub Pages |
| React/Vue 前端，不需要后端 | Vercel |
| Next.js 全栈 | Vercel |
| Node.js 后端 + 前端 | Railway |
| Python 后端 + 前端 | Railway |
| 想最简单，不想学 Git | 把 `dist/` 文件夹压缩发给用户 |
| 桌面应用 | electron-builder 打包 exe |

## 八、一句话总结

> [!tip] 部署 = 上传代码 + 平台自动构建
> ==前端用 Vercel，后端用 Railway，纯静态用 GitHub Pages。== 每次 `git push` 自动部署，零维护成本。
