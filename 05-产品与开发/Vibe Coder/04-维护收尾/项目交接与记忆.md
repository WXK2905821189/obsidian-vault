# 项目交接与记忆 — 三周后回来，你还能看懂自己的项目

> [!abstract] 这篇解决什么问题
> 三周后想加功能，打开项目——「这是 AI 写的，我不记得逻辑了。」==这篇教你用最少的时间，留下最有用的记忆锚点。==
>
> 前置阅读：[[05-产品与开发/Vibe Coder/Vibe Coder 常见问题全景图#4.1 想改但忘了之前怎么做的]]

---

## 一、三个必须留下的记忆锚点

| 锚点 | 是什么 | 一句话 | 何时创建 |
|---|---|---|---|
| **README.md** | 项目说明书 | 「这个项目干什么、怎么跑」 | 项目完成时 |
| **功能清单** | 回归测试清单 | 「现在有哪些功能、怎么验证」 | 每次迭代后更新 |
| **Git commit** | 版本历史 | 「每次改了什么」 | 每次迭代前 |

---

## 二、README.md — 最重要的记忆锚点

### 2.1 让 AI 帮你生成

```
"帮我写一份 README.md，用中文，说明：
1. 这个项目做什么（一句话 + 详细描述）
2. 怎么启动（npm install + npm run dev）
3. 怎么打包（npm run build）
4. 项目结构：每个文件夹放什么
5. 用了哪些技术
6. 有哪些注意事项
7. 已知问题和待优化点"
```

### 2.2 README 模板

```markdown
# 项目名称

一句话描述这个项目做什么。

## 快速开始

npm install
npm run dev

## 打包部署

npm run build
产物在 dist/ 文件夹

## 项目结构

src/          - 源代码
  components/ - 可复用组件
  pages/      - 页面
  utils/      - 工具函数
public/       - 静态资源

## 技术栈

- React + Vite
- Tailwind CSS
- localStorage 数据存储

## 功能列表

- [x] 用户注册和登录
- [x] 添加/删除/编辑笔记
- [x] 搜索笔记
- [ ] 笔记分类（待开发）

## 注意事项

- .env 文件需要配置 OPENAI_API_KEY
- 首次运行前需要 npm install
```

## 三、功能清单 — 迭代的记忆锚点

每次迭代后更新功能清单（详见 [[05-产品与开发/Vibe Coder/02-开发实战/Vibe Coding 迭代防退化指南#五、第三层：功能清单 + 回归测试]]）。

```
- [x] 用户注册：填写用户名+密码，点击注册，跳转到登录页
- [x] 用户登录：输入用户名+密码，点击登录，进入首页
- [x] 添加笔记：点击新建按钮，输入内容，保存后在列表显示
- [x] 删除笔记：点击删除按钮，确认后笔记从列表消失
- [x] 搜索笔记：输入关键词，列表实时筛选
- [ ] 笔记分类：按标签分类显示（v1.3 计划）
```

## 四、Git Commit — 版本的记忆锚点

每次 commit 写清楚做了什么（详见 [[05-产品与开发/Vibe Coder/02-开发实战/Git 极简生存指南]]）。

```bash
# ✅ 好的 commit message
git commit -m "v1.2 新增搜索功能：支持按标题和内容搜索"
git commit -m "v1.3 修复：登录页面在移动端样式错乱"
git commit -m "v1.4 重构：把用户管理拆成独立模块"

# ❌ 差的 commit message
git commit -m "改了一些东西"
git commit -m "update"
git commit -m "fix"
```

## 五、三周后回来的检查清单

打开项目后，按这个顺序恢复记忆：

```
□ 1. 读 README.md（回忆项目是什么、怎么跑）
□ 2. 读功能清单（回忆现在有哪些功能）
□ 3. git log --oneline（看最近改了什么）
□ 4. npm run dev（跑起来看看）
□ 5. 对 AI 说：「帮我回顾一下这个项目的核心逻辑」
```

---

## 六、一句话总结

> [!tip] 项目记忆 = README + 功能清单 + Git commit
> 做完项目花 5 分钟写 README，每次迭代花 10 秒更新功能清单，每次 commit 写清楚改了什么。==这 10 分钟会为你省下未来 3 小时的回忆时间。==
