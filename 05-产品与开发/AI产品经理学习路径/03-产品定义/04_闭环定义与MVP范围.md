# 闭环定义与MVP范围

> [!abstract] 本文要练成的能力
> 把一页产品定义收敛成**最小闭环 + MVP 范围**：画出"输入→AI→输出→价值"的闭环线，判断它转不转得起来，并把范围拆成 P0（必做）/P1（深化）/P2（后置）。这是能级2 的收口——**因为 AI 项目不确定性高，先让环转一圈拿到真实反馈，比憋大招做完再验证安全得多，所以范围控制是 AI PM 的基本功。**

---

## 一、深度讲透：闭环判定（用户用一次能否感到有用）

> 一个闭环成立的标志：**从"用户输入"到"拿到可用的输出"走通，且这个输出对用户有价值。**

> 判据一句话：**用户用一次，能不能立刻感到"这事有用"？** 能，就是闭环；不能，界面再全也是空架子。

> 因为 AI 项目的输出是概率性的，不实测就不知道行不行，所以**必须"先转一圈验证"再投入**；又因为 AI 项目有"模型成本 + 效果不确定 + 幻觉风险"三重变量，所以**一次改太多，出了问题根本定位不到是哪一环**——闭环越小，验证越快，返工越少。

> 深度洞察：**闭环的判据是"价值是否交付"，不是"功能是否齐全"。** 因为用户感知的是"我用一次有没有收获"，而不是"你有没有做满 16 个模块"，所以**任何不服务于闭环的功能都是成本**。

---

## 二、深度讲透：P0 / P1 / P2 优先级逻辑

> 优先级判断标准只有一条：**"没有它，闭环还转得起来吗？"**

| 级别 | 判定 | 例（InterviewPrep） |
|------|------|-------------------|
| **P0** | 没有它闭环不成立 | 岗位分析、能力诊断、单题练习、即时反馈、五维评分 |
| **P1** | 让闭环体验更好 | 更细的交互、历史记录、学习计划 |
| **P2** | 差异化上限，可后置 | 复杂的前沿功能、社区 |

> 因为 P0 是"闭环地基"，所以**铁律是"P2 再诱人，也要等 P0 闭环验证后再碰"**；又因为"先让闭环转起来，再让闭环转得深"是唯一正确的顺序，所以**优先级不是按"功能多诱人"排，而是按"没有它闭环还转吗"排。**

> 真实权衡：范围控制的反面是"范围蔓延"——每加一个 P2 功能，都推迟 P0 闭环的验证。**所以砍范围的判断标准是"这个功能对'用户用一次感到有用'有没有贡献"，没有就砍或后置。**

## 三、反例坑

> [!warning] 反例坑1：把"功能"当"闭环"
> 只做了"模拟面试"但没有评分反馈——用户练完不知道好不好，环没闭合，价值没交付。**因为"功能"是"环上的一段"，"闭环"是"整圈走通"，所以判断标准是"用户拿到可用的输出并感到有用"，而不是"按钮能点"。**

> [!warning] 反例坑2：憋大招
> 想一次性做完美再上线——**因为 AI 项目价值不确定，纸上谈兵没用，所以"看起来完整但没验证过核心价值"的产品，比"粗糙但闭环成立"的产品风险大得多**——前者可能上线即死，后者能拿到反馈迭代。你的 InterviewPrep 16 模块就是靠"先 P0 闭环、再 P1/P2 加深"做出来的。

## 四、填完即用：闭环定义表 + MVP 范围清单

### 模板1：最小闭环定义表

> 对每个候选需求填这张表。**填不满或填不通，说明还没想清楚，不要开始做。**

```
需求/场景：________
① 用户输入：________（用户给系统什么）
② AI 处理：________（AI 做什么，用哪种能力：生成/检索/分类/对话…）
③ 可用输出：________（用户拿到什么）
④ 价值判据：________（用户用一次，凭什么觉得有用？）
⑤ 兜底方案：________（AI 出错/超时/幻觉时怎么办）
```

### 模板2：MVP 范围清单（P0/P1/P2）

> 把候选功能按"没有它闭环还转吗"排进三档，**P0 全做完才叫 MVP 完成**。

```
产品：________

P0 必做（没有它闭环不成立）：
  □ ____  □ ____  □ ____
P1 深化（让闭环体验更好）：
  □ ____  □ ____
P2 后置（差异化上限，等 P0 验证后再碰）：
  □ ____
```

> 铁律：**P2 再诱人，也要等 P0 闭环验证后再碰。** 每轮只做一档，做完验证再进下一档。

## 五、示范：InterviewPrep 16 模块怎么排 P0/P1/P2

> 你的 InterviewPrep 有 16 个功能模块，按"闭环优先"重排如下，面试讲"从 0 到 1"时这就是范围控制的证据：

```
闭环线：岗位输入 → AI 解析 JD → 能力诊断 → 靶向练习 → 五维评分反馈

P0 必做（闭环地基）：
  岗位分析、能力诊断、单题练习、即时反馈、五维评分
  → 用户练一次：知道会被问什么、知道差在哪、拿到评分 → 闭环成立

P1 深化（体验更好）：
  历史记录、学习计划、热力图（投入线）、错题集
  → 让"连续练习 21 天准备度从 52 涨到 71"的成长可见

P2 后置（差异化上限）：
  复杂的前沿功能、社区、外部数据深度打通
  → 等 P0 验证后再碰，避免范围蔓延
```

> 注意：**P1 的"热力图 + 准备度"是留存设计，不是闭环必需**——它让用户看见成长，但闭环在 P0 已经成立。这就是"先闭环、再加深"的顺序。

## 七、练什么（可检验练习，结合真实项目）

- [ ] **练习1**：给 3 个真实需求（如"HR 制度问答""周报生成""简历诊断"）各画一条闭环线，填闭环定义表，判断哪条"转得起来"。
- [ ] **练习2**：把 InterviewPrep 的 16 个模块按 P0/P1/P2 重新过一遍，验证"没有它闭环还转吗"，找出哪些模块其实是 P2 却排进了 P0。
- [ ] **练习3**：找一个"功能很全但闭环没闭合"的产品（或你自己的半成品），指出它缺了闭环的哪一环，并补上缺失的那一环。

## 八、怎么算会（达标判据，可自测）

- [ ] 能对任意需求 5 分钟内画出闭环线，并说清"用户用一次凭什么觉得有用"。
- [ ] 能一眼判断一个功能是不是闭环的一部分，而不是"锦上添花"。
- [ ] 能拆出"从闭环到深度"的 P0/P1/P2 三档，并守住"P2 等 P0 验证后再碰"。
