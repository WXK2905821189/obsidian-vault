# 评测指标与容错设计

> [!abstract] 本文要练成的能力
> 为一页产品定义补上第 ⑤ ⑥ 栏：**定义"做对了"的评测体系（维度/评测集/评分标准/通过线）和"错了怎么办"的容错设计（幻觉兜底/转人工/置信度）。** 这是能级2 里最接近"能不能上线"的一环——**因为 AI 输出是概率性的，没有评测体系，你永远不知道产品到底行不行，所以评测能力是 AI PM 的核心标尺。**

---

## 一、深度讲透：评测能力是 AI 产品经理的核心标尺

> 大厂 AI PM 岗位 JD 里，出现频率最高的能力要求之一就是"**定义评测指标、建立评测体系**"。它约等于传统 PM 的"数据分析能力"——传统 PM 用数据判断功能好不好，AI PM 用评测判断**模型+产品**好不好。

> 很多 AI 产品上线后效果不稳定，**不是模型不够好，是评测体系没跟上**。因为模型会换、资料会更新、Prompt 会改，每次变更都改变输出质量；没有固定评测集，你就只能"凭感觉"判断变好还是变差，感觉不可复用、不可对比、不可解释。**所以评测体系不是"上线前的验收动作"，而是"每次迭代的标尺"。**

> 因为评测能力直接决定"你敢不敢上线、能不能迭代"，所以它是面试里最能体现"AI PM 专业度"的谈资——**讲项目时，能说出"我建了评测集、定了通过线、每轮只改一处"，比说"我调了 Prompt"高级一个量级。**

---

## 二、深度讲透：评测体系三要素

> 一套评测体系 = **评测维度 + 评测集 + 评分标准**，再加一条**通过线**。

```mermaid
flowchart LR
    A["评测维度<br/>评什么（结果层+过程层）"] --> B["评测集<br/>拿什么评（真实题+错题+边界题）"]
    B --> C["评分标准<br/>怎么打分（分档/量化）"]
    C --> D["通过线<br/>多少分能上线"]
```

### 要素1：评测维度（评什么）

> 分两层，各选 1~3 个可解释的，别贪多。

| 层 | 维度 | 定义 | 适用 |
|----|------|------|------|
| **结果层**（用户在意的） | 准确率/正确率 | 回答与期望一致的比例 | 有标准答案的问答 |
| | 覆盖率/命中率 | 该给的关键点是否都给到 | 结构化/摘要类 |
| | 引用准确率 | RAG 出处是否正确（防张冠李戴） | RAG 专用 |
| **过程层**（帮定位问题） | 检索命中率 | top_k 里有没有正确文档 | RAG 专用 |
| | 生成忠实度 | 生成有没有脱离检索内容胡编 | 生成类 |
| | 成本/延迟 | 每次调用的 token 与耗时 | 所有 |

> 取舍原则：**结果层判断"好不好"，过程层判断"为什么"。** 因为结果层变差时你不知道是哪一环的锅，所以配 1~2 个过程层指标定位。

### 要素2：评测集（拿什么评）

> 评测集 = **固定的输入样例 + 期望/参考答案**。三个来源，起步 30~60 条就够，关键是**固定、可复跑**。

| 来源 | 说明 | 例子（知微 RAG） |
|------|------|----------------|
| 真实问题 | 线上/用户问过的题，最有价值 | 用户真实提问截图入库 |
| 错题集 | 回答错/不理想的题，是增长点 | "引用张冠李戴"类问题 |
| 边界题 | 故意设计的刁钻/空值/无答案问题 | "只有一句话的问题、无答案问题" |

> 深度洞察：**错题集不是负面，是被评测集捕获、可被下一次迭代消除的东西。** 你知微机器人"周复盘 + 错题集"的底层逻辑就是这套——系统化后就从"随手记录"变成"正式评测资产"。

### 要素3：评分标准 + 通过线（怎么算过）

> 给每条样例打分，用分档而非模糊感受。示例四档：**正确 / 部分 / 幻觉 / 误拒**。然后定一条可接受红线，如"制度问答幻觉率 < 2% 才能上线"。

> 因为通过线是"敢不敢上线"的闸门，所以它必须**写在产品定义阶段**，而不是上线前临时拍脑袋——**先定通过线，再谈开发，评测才不会沦为事后解释。**

## 三、深度讲透：容错设计（错了怎么办）

> AI 无法 100% 正确，容错设计的本质是**控制错误落到用户身上的破坏力**。三件套：幻觉兜底、转人工、置信度。

| 手段 | 做法 | 适用 |
|------|------|------|
| **幻觉兜底** | 引用溯源（标出来源段落）、留底提示（"仅供参考"）、关键字段规则校验（数字/日期不靠 LLM 自检） | 中高风险生成类 |
| **转人工** | 检索不到可靠答案时明确说"我无法基于现有资料回答"，引导转人工/换入口（拒答 = graceful failure） | RAG 问答、客服 |
| **置信度** | 低置信时提示"可补充练习/请人工复核"，而不是硬给结论 | 评分、诊断类 |

> 因为兜底强度应正比于"出错代价"而非"AI 能省多少人力"，所以**低风险场景给人工闸门会拖慢体验、失去 AI 价值，高风险场景只留引用就上线等于把事故成本转嫁给用户**——分级配置，才能既敢快速迭代又不翻车。

> 真实权衡：容错不是越多越好。**每加一层兜底都加一层成本与体验摩擦**，所以先按风险分级，高风险上重兜底，低风险轻兜底。

## 四、填完即用：评测体系搭建模板

> 对每个 AI 功能填这张表，**四要素 + 通过线全填**，评测体系就立住了。

```
功能/场景：________

| 评测维度 | 评测集（来源+规模） | 评分标准 | 通过线 |
|---------|-------------------|---------|--------|
| （结果层：准确/覆盖/引用…） | （真实题+错题+边界题，30-60条） | （四档/量化打分） | （如幻觉率<2%） |
| （过程层：检索/成本…） | ____ | ____ | ____ |

容错设计：
- 幻觉兜底：____（引用/留底/字段校验）
- 转人工：____（拒答话术/人工入口）
- 置信度：____（低置信提示/人工复核）
```

> 示范（知微 RAG 机器人）：
> - 结果层：准确率 + 引用准确率；评测集 = 错题集 v3（52 条，含 12 条政策条款题）；评分四档（正确/部分/幻觉/误拒）；通过线 = 幻觉率 < 2%
> - 过程层：检索命中率（定位"答非所问"是不是检索的锅）
> - 容错：引用溯源 + 拒答转人工 + 关键字段（日期/天数）规则校验
> - 理由：因为制度回答会被员工当依据引用，所以通过线定严、兜底上重。

## 五、示范：知微机器人"周复盘 + 错题集"怎么变成评测体系

> 你的知微机器人已经跑过"周复盘 + 错题集"迭代流水线，本文把它升级成**正式评测体系**：

```
R6 只改 §评分Prompt：
  评测集：错题集 v3（52条，含12条政策条款题）
  结果：准确78%→81%（+3） 引用86%→84%（-2）
  结论：准确提升但引用下滑，方向部分正向，保留，引用待查。
  →下一轮R7：单改"检索重排阈值"验证引用。

R7 只改 检索阈值：
  评测集：同一错题集 v3
  结果：准确持平 引用84%→91%（+7）
  结论：正向，保留，建模为基线。
  →错题集补充2条例外题，升为v4。
```

> 核心：**每轮只改一处、跑同一评测集、记录"是否保留 + 为什么"**。因为一次改三处，改好了不知道谁的功劳、改差了不知道谁的锅，所以一次一动，让因果清晰。这套流程的正式版见 [[05-产品与开发/AI项目实战管理/02-AI特有管理篇/02_评测驱动迭代]]。
