# 大模型的原理：PM需要的直觉（重写版）

> [!abstract] 本文要练成的能力
> 把"大模型是概率续写器"这一条直觉，变成**一次真实产品决策里的可执行推敲**——不止会说"token/上下文/幻觉的定义"，还能在某次产品取舍中用它们下判断。这是能级1"技术判断"的第一块地基：**不懂它怎么工作，就谈不上判断它能不能做。**

---

## 一、一句话本质（先立住这三个推论）

> **大模型是一个"超级概率续写器"：根据你给它的上文，逐 token 预测"下一个最可能出现的词"，一个字一个字地续写出回复。**

这句看似简单，但三个推论直接决定产品设计取向：

1. **它生成，不保证正确** → 凡结果要"对"，都要在它外面加验证，不能让它自己兜底。
2. **输出随机可波动** → 同一输入多次结果可能不同，产品必须做"稳定性"与"可复现性"。
3. **它不知道知识是真是假** → 它只排序"哪个词更像"，不代表"哪个事实为真"。

> 因为它是"预测最像样"，不是"检索事实"，所以**当证据不足时它倾向编造一个最像样的答案（幻觉）**，而不是说"我不知道"。

---

## 二、四个核心概念 → 每个都给"产品后果"而非只给定义

| 概念 | 别再只会说定义 | 关键从"定义"到"取舍"的推敲 |
|------|--------------|---------------------------|
| **Token** | 模型读写的最小单位（词/子词） | Token 计价 = 产品成本未来线。因为你按 token 付费，所以**长输出、长输入会把单位成本放大**→ 估算每月调用量×平均 token 量，才能算清毛利。 |
| **上下文窗口** | 能"同时看到"的输入长度 | 窗口是**有限且共享的预算**。因为总量固定，所以"塞更多资料"必然挤占"生成空间"→ 超长文档不能硬塞，要检索/分段。 |
| **幻觉** | 编造看似合理但不实的内容 | 幻觉是**概率随机的、无法100%消除**。所以凡高风险结论都需"机制兜底"而非"祈祷提示词"。 |
| **温度/采样** | 控制随机性 | 温度高=更发散更有创意，温度低=更稳定更可复现。**所以创作类要高温度，事实/逻辑类要低温度**，是一个可见的产品旋钮。 |

> 深度洞察：**这四件事本质是同一件事的两个面——"有限且随机的生成资源"。** 上下文是空间的有限，token 是价格的有限，幻觉是正确性的随机，温度是风格的随机。因为资源既有限又随机，所以 **AI PM 的核心工作之一就是"做资源分配与失败兜底"**，这与传统产品的"需求与成本取舍"同构。

## 三、D1 实操模板：一次产品决策中如何用到这些概念

> 当你要为一个需求做"是否用AI、用什么"的初判时，用这张表逐项走，填完即给出决策依据。

```
产品决策推敲表：
需求：____（一句话）
① 输出需要"绝对正确"吗？是→必须外部校验；否→可原生生成
② 每次对话平均来回多少 token？____→估算单次成本与月度成本
③ 需要的资料量是否接近/超出上下文窗口？____→决定要不要检索
④ 输出可接受"每次略有不同"吗？否→把温度调到低，并固化prompt
⑤ 若出错，最坏代价多大？____→决定兜底强度（见←幻觉分级表）
结论（用这些概念支撑，而非拍脑袋）：____
```

**一个真实例子（HR场景）**：

> 需求："面试评估生成"。假设结构化面试，要求输出评分与建议。
> - ① 需要正确：评分须准 → 强制校验字段，AI 只写评语、不打分，或打分后规则复核。
> - ② 一份面试记录约 3000 token 输入、议 500 token 输出 → 单次约 0.01 元级，日均 100 份 ≈ 月成本可估算，能支撑定价。
> - ③ 若把全公司岗位 JD 都塞进 prompt（超窗口）→ 挤占生成空间且检索不精准 → 改为只检索该岗位 JD（RAG），保证评语有据。
> - ④ 面试评语要规范稳定 → 温度低、示例固化。
> - ⑤ 评语出错影响用人决策但可人工复核 → 中等兜底（引用+人工review）。

这就是"用这4个概念做取舍"的样子：**每个概念都落到一个产品开关，而不是背定义。**

> 与你背景衔接：你做的**多LLM链重构**，本质就是在解决"单一模型立场不统一/格式不稳定"——这正是"输出波动"（直觉2）+ "上下文分工"（概念2）的产品化处理。

## 四、D2 深度洞察：三个最容易踩的坑

1. **把"能写"当成"能保证"（最常见的翻车）**
   → 因为模型会流畅地编造，所以**"看起来专业"并不等于"正确"**。HR 制度问答若无引用，AI 会自信地给出错误制度，代价极高。这就是你知微机器人必须上"引用溯源"的原因。

2. **把上下文窗口当"无限内存"**
   → 因为窗口是共享预算，所以**塞越多资料、生成越稀薄且越快出错**。把 10 万字说明书全塞进一个 prompt 是错误示范，正确做法是检索关键片段。

3. **把"换更强的模型"当唯一解法**
   → 因为能力随代际快速变化，所以**产品判断必须基于"当前这版能做什么"**，而非想象"下一代会更好"。能靠产品机制解决的问题（引用/校验/分段），不要指望换模型解决。

> 给求职的运用：面试问"某个 AI 应用为什么失败/局限"，用这套直觉答：**"此场景难点在 X，因为大模型擅长/不擅长 Y（基于概率续写机制），所以我用 Z（引用/校验/分段）来兜底。"** 这比背概念更有说服力。

## 五、D3 主线衔接

- **衔接能级1自身**：本文立的"有限+随机+需要兜底"三推论，是后面所有技术选型、能力边界判断的思想底座。
- **衔接能级2 产品定义**：当你设计 AI 产品时，**凡是"要确定性结果"的需求点**，都要提前标注"需要额外验证机制"——这就是把技术直觉翻译成产品需求取舍的开始。
- 显式衔接判据：**能对自己的需求，说出"这里要确定性/这里能容错"，就是你从"懂直觉"走向"会下产品判断"的分界。**
