# 07_HR数据分析实战：招聘漏斗、离职预测、绩效校准

> [!abstract] 一句话总结
> 本文针对HR从业者最常遇到的三个数据分析场景：招聘漏斗分析、离职分析与预测、绩效数据校准，每个场景都提供"AI辅助分析→人做判断"的完整流程、模板和提示词。读完就能用。

---

## 一、场景一：招聘漏斗分析

### 1.1 问题定义

**典型场景：** "最近招聘效率好像下降了，但我不确定问题出在哪。"

**转化为可分析的问题：**
- 招聘漏斗各环节的转化率是多少？哪个环节流失最严重？
- 不同渠道的漏斗表现有什么差异？
- 不同岗位类型的漏斗表现有什么差异？
- 转化率的时间趋势是怎样的？是持续下降还是阶段性波动？

### 1.2 指标定义

| 指标 | 计算公式 | 含义 |
|------|---------|------|
| 简历筛选转化率 | 面试人数 / 投递人数 | 简历质量 + 筛选标准 |
| 面试到Offer转化率 | Offer人数 / 面试人数 | 面试质量 + 候选人匹配度 |
| Offer接受率 | 入职人数 / Offer人数 | 薪资竞争力 + 候选人意向 |
| 整体转化率 | 入职人数 / 投递人数 | 招聘效率综合指标 |
| 平均招聘周期 | 入职日期 - 需求提出日期 | 招聘速度 |
| 各环节平均耗时 | 下一环节时间 - 上一环节时间 | 流程瓶颈识别 |

### 1.3 数据准备

**需要的数据：**

| 字段 | 说明 | 示例 |
|------|------|------|
| 岗位ID | 唯一标识每个招聘岗位 | REQ-2026-001 |
| 岗位名称 | 岗位名称 | 高级Java开发 |
| 部门 | 所属部门 | 技术部 |
| 渠道 | 招聘渠道 | Boss直聘、猎头、内推 |
| 投递日期 | 候选人投递日期 | 2026-03-15 |
| 筛选通过日期 | 简历筛选通过日期 | 2026-03-18 |
| 面试日期 | 第一轮面试日期 | 2026-03-22 |
| Offer日期 | 发放Offer日期 | 2026-04-01 |
| 入职日期 | 实际入职日期 | 2026-04-15 |
| 状态 | 当前状态 | 已入职/Offer拒绝/面试未通过/筛选未通过 |

### 1.4 AI辅助分析

**步骤1：上传数据，描述分析目标**

```
提示词：
"这是我们的招聘数据（2026年Q1-Q2），包含字段：岗位ID、岗位名称、部门、渠道、投递日期、筛选通过日期、面试日期、Offer日期、入职日期、状态。

请帮我做一个完整的招聘漏斗分析：
1. 计算整体招聘漏斗：投递→筛选→面试→Offer→入职，各环节的转化率和人数
2. 按渠道分组，对比各渠道的漏斗表现，找出转化率最高和最低的渠道
3. 按岗位类型分组，对比不同岗位的漏斗差异
4. 按月份展示整体转化率趋势，用折线图
5. 计算各环节的平均耗时，找出流程瓶颈
6. 给出3-5个优化建议"
```

**步骤2：验证AI的输出**

| 验证项 | 怎么验证 |
|--------|---------|
| 数据量 | 各环节人数之和是否合理？有没有人"跳过"某个环节？ |
| 转化率 | 是否可能出现"面试人数>投递人数"等不合理情况？ |
| 时间计算 | 日期格式是否正确？有没有负的耗时？ |
| 分组逻辑 | 渠道/岗位的分组是否合理？有没有遗漏的类别？ |

**步骤3：深入追问**

```
追问：
"请进一步分析：
1. 筛选到面试环节耗时最长（平均5天），是哪些岗位/部门？
2. 面试到Offer转化率最低（35%），分析可能的原因：
   - 是薪资问题？（对比Offer接受率）
   - 是面试体验问题？（对比面试后候选人的反馈）
   - 是竞争问题？（对比竞品Offer的情况）
3. 如果只优化一个环节，应该选哪个？为什么？"
```

### 1.5 洞察输出示例

```
核心发现：招聘漏斗的瓶颈在"面试到Offer"环节，转化率仅35%，且持续下降。

归因分析：
- 降幅集中在薪资要求较高的候选人（月薪>25K的候选人Offer接受率仅20%）
- 竞品分析显示，同岗位我们的薪资处于市场50分位，而候选人期望在75分位
- 面试到Offer的平均耗时15天，期间候选人收到了其他Offer

行动建议（按优先级）：
P0：将技术岗薪资范围上调10-15%，对标市场75分位
P0：将面试到Offer流程压缩至7天内
P1：在面试环节增加薪资预期对齐，避免Offer阶段谈崩
P2：建立"候选人体验跟踪"，在面试后48小时内收集反馈
```

## 二、场景二：离职分析与预测

### 2.1 问题定义

**典型场景：** "最近离职的人有点多，老板让我分析一下原因。"

**转化为可分析的问题：**
- 离职率是多少？与历史相比是什么水平？
- 哪些部门/岗位/入职年限的离职率最高？
- 离职的主要原因是什么？
- 能否提前识别"高离职风险"员工？

### 2.2 指标定义

| 指标 | 计算公式 | 含义 |
|------|---------|------|
| 月度离职率 | 当月离职人数 / 月初在职人数 | 人才流失速度 |
| 年度离职率 | 全年离职人数 / 年均在职人数 | 年度人才保留情况 |
| 主动离职率 | 主动离职 / 总离职 | 员工主动流失（排除裁员） |
| 新员工离职率 | 入职<6个月的离职 / 入职<6个月的总数 | 招聘和入职质量 |
| 关键人才离职率 | 高绩效/高潜员工的离职率 | 核心人才流失 |
| 离职原因分布 | 各类离职原因占比 | 离职根因分析 |

### 2.3 数据准备

**需要的数据：**

| 字段 | 说明 |
|------|------|
| 员工ID | 唯一标识 |
| 部门 | 所属部门 |
| 岗位 | 岗位名称 |
| 入职日期 | 入职时间 |
| 离职日期 | 离职时间（如未离职则为空） |
| 离职类型 | 主动离职/被动离职 |
| 离职原因 | 薪酬/发展/文化/个人/其他 |
| 绩效评分 | 最近一次绩效评分 |
| 薪资 | 月薪或年薪 |
| 司龄 | 入职到现在的年限 |

**如果你想做离职预测，还需要：**
- 最近3次的绩效评分趋势
- 出勤情况（是否有异常请假）
- 晋升历史（上次晋升时间）
- 培训参与情况

### 2.4 AI辅助分析

**步骤1：描述性分析**

```
提示词：
"这是我们的员工离职数据（2025-2026），包含字段：员工ID、部门、岗位、入职日期、离职日期、离职类型、离职原因、绩效评分、薪资、司龄。

请帮我分析：
1. 整体离职率及各月趋势（折线图）
2. 按部门分组，各月离职率对比（多线折线图）
3. 离职原因分布（饼图或柱状图）
4. 离职员工的司龄分布（直方图）——判断是新员工流失还是老员工流失
5. 离职员工的绩效分布——是低绩效者流失还是高绩效者流失
6. 按部门×离职原因做交叉分析，找出各部的'离职画像'"
```

**步骤2：预测分析（进阶）**

```
提示词：
"基于这份员工数据，请帮我做一个离职预测分析：
1. 用逻辑回归分析哪些因素最能预测离职（列出Top 5影响因素及其影响力）
2. 分析绩效评分的趋势——离职前绩效是下降还是上升？
3. 分析司龄——是否存在'离职高危期'（如入职6个月、2年、5年）
4. 如果你要给CEO一个'离职预警模型'的建议，你会推荐关注哪些指标？"
```

**步骤3：验证AI的结论**

- [ ] 离职率计算是否正确？（自己用手算验证一下）
- [ ] 分组的样本量是否足够？（<30人的部门，离职率波动大，结论不可靠）
- [ ] 影响因素分析是否合理？（"薪资"影响离职，但可能薪资是"代理变量"，真正的因素是"岗位级别"）
- [ ] 预测模型的准确性如何？（AI应该报告准确率/召回率）

### 2.5 洞察输出示例

```
核心发现：离职率的上升，根因不是薪资，而是"成长空间"。

数据证据：
- 离职原因中，"发展受限"占比42%（排名第一），"薪资"仅占18%
- 离职高峰出现在司龄2-3年（入职2-3年的员工离职率是其他阶段的3倍）
- 离职员工中，高绩效者占比60%（说明我们在流失核心人才）

归因分析：
- 2-3年司龄是"职业倦怠期"：已熟悉工作，但看不到晋升路径
- 高绩效者离职可能因为"想做的事"和"在做的事"有落差

行动建议：
P0：建立"关键人才保留计划"，对高绩效+司龄2-3年的员工进行一对一职业发展对话
P0：加快内部晋升通道，缩短"可晋升"的等待时间
P1：建立离职预警机制：监控异常请假、绩效趋势下降等信号
P2：每季度做一次"高离职风险员工"筛查，提前介入
```

## 三、场景三：绩效数据校准

### 3.1 问题定义

**典型场景：** "绩效评分出来了，但销售部平均分4.5，技术部平均分3.2，这合理吗？是不是销售部经理打分太松了？"

**转化为可分析的问题：**
- 各部门的绩效分布是否合理？是否存在"打分手松"或"打分严苛"？
- 绩效评分与客观指标（如销售额、代码提交量）是否一致？
- 强制分布是否合理？是否需要校准？

### 3.2 指标定义

| 指标 | 计算公式 | 含义 |
|------|---------|------|
| 部门平均分 | 部门所有员工绩效分均值 | 部门间打分松紧度对比 |
| 部门标准差 | 部门绩效分的标准差 | 部门内打分区分度 |
| 绩效-产出比 | 绩效分 / 客观产出指标 | 验证"高分是否对应高产出" |
| 强制分布偏差 | 实际分布 vs 目标分布 | 是否需要校准 |

### 3.3 AI辅助分析

```
提示词：
"这是我们的绩效数据，包含字段：员工ID、部门、经理、绩效评分、绩效等级、销售额（如有）、项目完成数（如有）。

请帮我做绩效校准分析：
1. 各部门绩效评分的分布对比（箱线图或小提琴图）
2. 各部门绩效各等级的比例对比（堆叠柱状图）
3. 哪些经理的评分显著偏离部门平均水平（可能需要校准）
4. 如果有客观产出指标（销售额），分析绩效评分与客观产出的相关性
5. 给出校准建议：哪些部门/经理需要调整评分"
```

### 3.4 洞察输出示例

```
核心发现：销售部评分偏高，但客观产出数据支持高分；技术部评分偏低，但区分度不足。

数据证据：
- 销售部平均分4.5，技术部平均分3.2
- 但销售部绩效分与销售额的相关系数0.78（强相关），说明高分确实对应高产出
- 技术部标准差仅0.3（大部分人在3.0-3.5之间），区分度不足

建议：
- 技术部不需要"拉高平均分"，但需要"拉大区分度"——让优秀的人和普通的人拉开差距
- 建议技术部经理参加"绩效面谈培训"，学习如何做有区分度的评估
- 引入"绩效校准会"机制：各部门经理一起讨论评分标准，对齐尺度
```

## 四、HR数据分析的AI提示词库

### 4.1 通用模板

```
"我有一份HR数据，包含以下字段：[列出字段]。
请帮我做以下分析：
1. 描述性统计：[你要的描述统计]
2. 分组对比：[你要的分组维度]
3. 趋势分析：[你要的时间维度]
4. 异常检测：[你要检查的异常类型]
5. 优化建议：[你要的洞察方向]

输出要求：
- 图表类型：[柱状图/折线图/散点图等]
- 报告格式：Markdown
- 语言：简洁，非技术人员能看懂"
```

### 4.2 场景化提示词

| 场景 | 提示词关键句 |
|------|-------------|
| 招聘效率 | "分析招聘漏斗各环节转化率，找出瓶颈环节" |
| 渠道分析 | "对比各渠道的ROI（成本/入职人数）和转化率" |
| 离职分析 | "分析离职率趋势、原因分布、影响因素排序" |
| 绩效校准 | "对比各部门评分分布，找出打分偏松/偏严的部门" |
| 培训ROI | "对比培训前后的绩效变化，估算培训的投资回报" |
| 人效分析 | "分析人均产出、人均利润的部门差异和趋势" |
| 薪酬分析 | "分析薪酬与绩效的关系，找出薪酬竞争力问题" |

---

> [!quote] 最后一句
> HR数据分析不是"技术活"，而是"业务活"。你的价值不在于"会不会写SQL"，而在于"能不能从数据中发现业务问题并推动改变"。AI帮你踢开技术门槛，你来做最有价值的事——理解人、理解组织、推动决策。
